# Fathom

毎日出会う英語を「見た瞬間に分かる」ようにするための、ひとり用の学習アプリ（PWA）。
中学英語の途中で止まったままの大人が、文の骨組みから読み直す。

サーバーなし、AIの呼び出しなし、ビルドなし。素の HTML / CSS / JavaScript。

## 守ること（設計の約束）

- 制限時間、失敗音、ライフ制は入れない。間違えても静かに解説を出すだけ。
- 説明は大人向け。「説明の階段は低く、見渡す世界の天井は低くしない」。
- 文法の「なぜ」は、意味と使い方の説明を優先する。歴史や由来は確かなものだけ書く。不確かなら書かない。
- 読解と聴解は別々に記録する。音声で確かめていない項目は「未測定」。読解から推測しない。
- 一度の正解、偶然の正解で「分かる」にしない（規則は下の「学習の規則」）。
- 反応時間は記録するだけ。判定に使わない。
- 文法の順番は強制しない。地図のどこからでも入れる。
- 数より品質。問いは「構造が分からないと答えられない」ものにする。

## 動かし方

`index.html` を直接開いても動かない（教材を1文ずつ読み込むため）。簡易サーバーを使う。

```
powershell -ExecutionPolicy Bypass -File tools/serve.ps1
```

→ http://localhost:8123/ を開く。動作確認は http://localhost:8123/tests.html 。

このPCの注意: `python` と打つと Microsoft Store の空のコマンドが先に呼ばれて失敗する。
本物は `%LOCALAPPDATA%\Python\bin\python.exe`。Node.js は入っていない。
git も PATH に無い。GitHub Desktop に入っているもの（`%LOCALAPPDATA%\GitHubDesktop\app-*\resources\app\git\cmd\git.exe`）を使う。
アプリ内のブラウザ枠と、英語の音声を入れていない Windows には、英語の読み上げの声が無い（日本語の声だけ）。聞く入口は Edge か Chrome で確かめる。

スマホのホーム画面に置くには https での公開が必要（GitHub Pages など。公開先は未定）。
フォルダをそのまま置けば動く。パスはすべて相対なので、サブフォルダ配下でもよい。

## 構成

```
index.html              画面の枠（タブ4つ）
tests.html              動作確認ページ
manifest.webmanifest    PWA の設定
sw.js                   アプリ本体のオフライン対応
css/style.css           見た目（明暗どちらも）
js/app.js               画面と操作
js/learn.js             学習の規則（純粋な関数。状態判定・復習の間隔・1回分の文選び）
js/store.js             学習記録の保存・書き出し・読み込み・形式の変換
js/data.js              教材の読み込み・検査・端末への保存と更新
js/tests.js             tests.html の中身
data/index.json         文の一覧（出す順番）と、音声ファイルのある文
data/grammar.json       文法の地図（グループ、項目、説明）
data/sentences/*.json   文（1文1ファイル）
audio/                  音声ファイル置き場（今は空。無ければブラウザの読み上げ）
icons/                  アイコン
tools/serve.ps1         確認用サーバー
tools/add_sentences.py  文をまとめて追加する道具
```

画面は4つ。**今日**（1回5文。読む／聞く）、**地図**（文法の一覧と各項目の説明・状態・文）、**単語帳**、**記録**（設定、書き出し・読み込み、教材の更新）。

## 文のデータ

`data/sentences/r-0003.json`:

```json
{
  "id": "r-0003",
  "shelf": "read",
  "en": "She sent me the link.",
  "ja": "彼女が私にそのリンクを送ってくれました。",
  "scene": "友人とのやりとりを説明する投稿で",
  "grammar": ["svoo", "past", "pronoun"],
  "aim": "動詞の後ろに名詞が2つ。1つ目が受け取る人、2つ目が渡す物。",
  "pitfall": "「に」「を」にあたる言葉がないので、順番を見ないと誰が受け取ったか分からない。",
  "chunks": [
    { "text": "She", "role": "S", "plain": "誰が" },
    { "text": "sent", "role": "V", "why": "send（送る）の過去形。-ed を付けない不規則動詞。" },
    { "text": "me", "role": "O", "plain": "誰に", "why": "I ではなく me。動詞の後ろに来たときの形。" },
    { "text": "the link", "role": "O", "plain": "何を" }
  ],
  "words": [
    { "w": "sent", "lemma": "send", "ja": "送る（sent は過去形）" },
    { "w": "link", "lemma": "link", "ja": "リンク" }
  ],
  "question": {
    "ask": "リンクを受け取ったのは誰？",
    "choices": ["この文を書いた人", "彼女", "まだ誰も受け取っていない"],
    "answer": 0,
    "explain": "sent の直後の me が受け取る人、その次の the link が送られた物。送ったのは She です。"
  }
}
```

| 項目 | 意味 |
|---|---|
| `id` | 一度付けたら変えない。学習記録はこの id で文とつながる。`r-`＝読む棚、`t-`＝話す棚。ファイル名と同じにする |
| `shelf` | `read`（SNS・AI関連で出会う文）か `talk`（近所での会話） |
| `en` / `ja` | 英文と訳 |
| `scene` | どこで出会う文か（省略可） |
| `grammar` | `data/grammar.json` の項目 id。この文で実際に効いている項目だけ（1〜3個） |
| `aim` | 何を理解させたい文か |
| `pitfall` | 誤解しやすい点 |
| `chunks` | 骨組み。`text` を順につなぐと `en` になること（記号と大文字小文字は無視） |
| `chunks[].role` | `S` 主語 / `V` 動詞 / `O` 目的語 / `C` 補語 / `M` 修飾語 / `aux` 助動詞 / `neg` 否定 / `q` 疑問詞 / `conj` 接続詞 / `x` その他（`plain` 必須）。色とラベルの既定値が決まる（`js/data.js` の `ROLES`） |
| `chunks[].plain` / `term` | ラベルの上書き。`plain`＝ふだんの言葉、`term`＝文法用語。省くと `role` の既定値 |
| `chunks[].why` | なぜその形か（省略可。助動詞・否定・疑問の部品や、形が変わった動詞には書く） |
| `words` | タップできる単語。`w`＝文中の形（2語以上も可。1つの chunk に収まっていること）、`lemma`＝原形（単語帳と再会はこれで束ねる）、`ja`＝この文での意味 |
| `question` | 理解確認の問い。`answer` は `choices` の位置（0始まり）。表示のたびに並び順は混ぜるので、正解を何番目に書いてもよい。「まだ分からない」は画面が自動で足す |
| `question.targets` | その問いが実際に確かめている文法項目（`grammar` の一部）。正誤はここに書いた項目にだけ数える。省くと `grammar` 全部に数えるので、**新しい文には必ず書く**（例: `["svoo"]`）。文に the が出てくるだけで a / the を問うていないなら、`article` は `grammar` に残しても `targets` には入れない |
| `audioId` | 音声ファイルと結ぶ id。省くと `id` と同じ |

検査は `js/data.js` の `validate` が行う。通らない文は読み込まれず、「記録」タブと tests.html に理由が出る。

### 文を足す

1. `data/sentences/<id>.json` を作る（上の形）。
2. `data/index.json` の `sentences` に id を1行足す。並び順が、新しい文として出る順番。
3. tests.html を開いて、検査に通ることを確かめる。

まとめて足すときは、文を並べた JSON 配列のファイルを作って:

```
%LOCALAPPDATA%\Python\bin\python.exe tools/add_sentences.py まとめファイル.json
```

文を足しても学習記録は変わらない。開いたままのアプリには、次に開いたとき（または「記録」→「教材の更新を確認」）で入る。

### 文を作るときの基準

- 問いは、単語の意味を知っているだけでは答えられず、構造（誰が・誰に・何を、否定か質問か、いつの話か、どこにかかるか）を取れて初めて答えられるものにする。誤答の選択肢は、その文で実際に起きやすい誤読にする。
- 同じ文法を、違う単語・違う場面で。同じ文の言い換えを増やさない。
- 1つの文法項目に、それを確かめる問い（`targets` に入っている文）を最低3本。「分かる」には、別々の文での正解が2回要るため。tests.html が本数不足を指摘する。
- 同じ単語（lemma）が複数の文に出るようにすると、単語帳の「再会」が働く。
- 読む棚は、実在の投稿の引用ではなく、その種類の文を自作する。

### 文法の地図

`data/grammar.json` の `items` に `{ id, group, name, pattern, what, why }`。`what` は意味と使い方、`why` はなぜその形か。`\n` で段落を分ける。id は文の `grammar` から参照されるので変えない。項目を足したら、その項目の文も3本以上足す。

### 音声を差し替える

`audio/<audioId>.mp3` を置き、`data/index.json` の `audio` 配列にその `audioId` を足す。載っている文はファイルを再生し、載っていない文はブラウザの読み上げを使う。学習記録は文の id に付いているので、音声を替えても履歴は続く。一度再生した音声は端末に保存される。

## 学習記録

端末の localStorage（キー `fathom.progress`）に保存。形式のバージョンは `js/store.js` の `VERSION`（現在 1）。

```json
{
  "version": 1,
  "createdAt": 1731200000000,
  "events": [
    { "t": 1731200000000, "sid": "r-0003", "mode": "read", "helped": false, "correct": true, "choice": 0, "ms": 4200 }
  ],
  "words": { "send": { "addedAt": 1731200000000, "metIn": ["r-0003"], "ja": "送る（sent は過去形）" } },
  "settings": { "shelf": "both", "sound": true, "labels": "plain", "rate": 0.9 }
}
```

- `events` は起きたことをそのまま残すだけ。`mode` は `read` / `listen`。`helped` は「答える前に分解・単語・（聞くときは）英文を見た」。`correct: null` は「見ただけで答えなかった」（分解を開いた瞬間と、答えずにカードを離れたときに残す）。`choice: -1` は「まだ分からない」。`ms` は反応時間（判定には使わない）。`heard: false` は、聞く入口で音声が再生できなかった回。
- 地図で文法の解説を開いたことも残す: `{ "t": …, "sid": "", "gid": "be", "mode": "map", "correct": null }`（1項目につき1日1回）。
- 保存の直前に、端末にある記録と合わせる（別タブやホーム画面のアプリで足された記録を消さないため）。別の画面で記録が変わったら読み直す。
- 状態（勉強中・分かる など）は保存しない。毎回 `events` から計算する。だから規則を直しても過去の記録は生きる。
- 形式を変えるときは `VERSION` を上げ、`MIGRATIONS[旧バージョン]` に変換関数を足す。古い書き出しファイルもそれで読める。
- 書き出しは JSON ファイル（または文字で表示）。読み込みは「合流」で、今ある記録を消さず、同じ記録は重ねない。形の合わない記録が1件でも混ざっていたら、何も変えずに断る。

## 学習の規則（`js/learn.js`）

1つの文には複数の文法項目が付くので、「初見」などの区別は **文法項目ごと** に、記録から導く。正誤を数えるのは、その問いの `targets` に入っている項目だけ。読むと聞くは、日付の管理も含めて別々（読んだ日を、聞く側の「前に触れた日」に使わない）。

| 区分 | 条件 |
|---|---|
| 初見 `first` | その項目に初めて出会った文に、自力で答えた |
| 解説後 `assisted` | 分解・単語・英文表示を見てから答えた |
| 数日後の初見 `delayed` | その項目に前回触れたのが別の日で、初めて見る別の文に、自力で答えた |
| 久しぶりの文 `revisit` | 30日以上前に見た文に、自力で答えた |
| `unheard` | 聞く入口で、音声が再生できなかった |
| `sameday` | 同じ日にその項目に触れたあと（別の文に答えた、または地図で解説を読んだ）、別の文に自力で答えた |
| `repeat` | 30日以内に見た同じ文にもう一度答えた（文を覚えているだけかもしれない）。聞く側では、同じ日に読んだ文もこれ |
| `view` | 見ただけ |

状態（読解・聴解それぞれ別に計算）:

- **未探索**（聴解は **未測定**）: 記録なし
- **勉強中**: 記録はあるが、下に届かない
- **読めば分かる／聞いても分かる**: 「数日後の初見」か「久しぶりの文」の正解が、別々の日・別々の文で2回以上あり、そのうち1回以上は「数日後の初見」で、かつ直近のそれが正解

復習: 文法項目ごとに、最後に触れた日から 1 → 3 → 7 → 14 → 30 日後（「数日後の初見」の連続正解数で進む。直近が不正解なら1日）。復習日が来たら、その項目を確かめる **別の文** を出す。初めての文が残っていなければ、今日は見ていない既出の文で復習する（判定には数えないが、項目は落とさない）。単語帳の単語も同じ間隔で、入れた文とは別の文の中に出す。

1回分（5文）の選び方: ①復習日が来た文法項目の別の文（最大3）→ ②単語の再会（最大2）→ ③読みかけで離れた文 → まだ見ていない文を `index.json` の順に → ④足りなければ見た日が古い文。聞く入口は、読んだことのある文だけを、最近聞いていない順に。

## オフラインと更新

- アプリ本体（HTML・CSS・JS）: `sw.js` が保存する。ネット優先で、つながらなければ保存済みを使う。ファイルを足したら `sw.js` の `FILES` に足す。
- 教材（`data/`）: `js/data.js` が自分で端末に保存する（Cache Storage の `fathom-data`）。起動時は保存済みから即座に開き、裏で最新を取りに行って、変わっていれば差し替える。初回だけネットが必要。取り直した教材は、全体が開ける形か検査してから保存する（壊れた更新で、保存済みを上書きしない）。「教材は最新です」と出すのは、すべて取り直せたときだけ。
- 音声（`audio/`）: `sw.js` が保存する。保存済みをすぐ返しつつ裏で取り直すので、同じ名前で差し替えた音声は次に聞くときから新しくなる。
- 学習記録は教材とは別の場所にあるので、教材やアプリを更新しても消えない。

## 確認したこと（tests.html と手動）

- 学習の規則（一度の正解で習得にならない、同日の正解・解説後・同じ文の再回答・解説を読んだ日の正解・音声が出なかった回は数えない、聴解は読解の日付を借りない、反応時間は無関係、間隔の伸び方、棚・地図からの絞り込み、単語の再会、問いが確かめていない文法には数えない）
- 書き出し → 読み込みでの復元、二重読み込みで重複しない、合流、形式違いの拒否
- 再読み込み後も記録が残る／サーバーを止めた状態で再読み込みしても教材と記録が開く
- 文を足すと、記録を保ったまま反映される

## できているもの・まだのもの

できている:

- 教材: 文 101 本（読む棚 58・話す棚 43）、文法 33 項目。全文に `question.targets` を記入済みで、どの項目にも、それを確かめる問いが3本以上ある
- 核の7つ（文のデータ、読む流れ、分解、文法の地図、単語帳、復習、保存と引き継ぎ）
- 聞く入口（ブラウザの読み上げ。声は「記録」で選べる。英語の声が無い環境では、日本語の声に読ませず、その旨を出す。音声ファイルへの差し替え口あり）
- 控えめな正解音（設定で消せる）

まだ（設計だけ）:

- **作る入口**: 「読めば分かる」になった文法の文だけを対象に、`ja` と `scene` を見せて英語を組み立てる。段階は ①`chunks` の並べ替え（`chunks[].text` を混ぜて並べ直す。データは今のままで足りる）→ ②頭の中で言ってから正解を見る（自己申告のみ、判定しない）。記録は `mode: "make"` を足す。`learn.js` は `listen` 以外をすべて読解として数えているので、足すときは `mode === 'read'` に絞るよう直すこと。地図には3つ目の印として出す。強制せず、今日の画面に独立した入口を置く。
- **高速スライド**: 読解が「分かる」の項目だけを含む、既読の文を、自分で選んだ秒数（例 2 / 3 / 5秒）で流す。判定なし、記録は取らない（取るなら `correct: null` の `view` として）。一時停止と、止めた文の分解へのリンクを付ける。
- **いじれる例文**: 主語（I / you / he / they）× 時（現在・過去・未来）× 形（肯定・否定・疑問）を切り替えると文が変形する。教材とは別に、`data/playground.json` に動詞の活用表（be、規則動詞、主な不規則動詞の原形・三単現・過去形）を持たせ、変形は関数で作る。どの部品が動いたかを色で示し、`grammar.json` の `negative` / `question` / `s3` / `past` の説明へつなぐ。地図の該当項目から入れるようにする。
- 特定の声の音声（置き場と結び方は用意済み。上の「音声を差し替える」）
- 公開先（未定）

最初の版に入れないと決めたもの: 貼った英文の自動分解、音声の生成、発話の判定。
